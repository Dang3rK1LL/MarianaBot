# Validation and milestones

## Development environment

Windows, Python 3.11.2, Codex CLI 0.154.0, Claude Code 2.1.257.

## Offline validation

Final local result: **29 tests passed**, Ruff lint/format checks passed, dependency
consistency passed, and an installable Python wheel built successfully.

The offline suite also exercises the dashboard under a legacy Windows output
encoding, preventing non-ASCII status symbols from crashing the CLI.

The test suite covers:

- Full MB → RB specialists → RB chair → JB critics → JB chair loops.
- Durable exports and per-agent response reuse after interruption.
- Owner steering and asynchronous MB answers using shared OpenAI capacity.
- Immediate cancellation and pause during quota waits.
- Persistent primary/secondary quota resets and unknown-reset fallback.
- Billing failures distinguished from subscription rate limits.
- Duplicate mailbox reads without duplicate inference.
- Judge schema rejection, sustained approval, blockers, human-evidence and time limits.
- Real subprocess fixtures for Codex JSONL/app-server RPC and Claude stream JSON.
- Removal of API-key overrides, diagnostic redaction, and permanent stop behavior.

The demo is deterministic, performs no network calls, and validates product flow.
GitHub Actions runs the offline suite and demo on Windows/Ubuntu with Python
3.11/3.13. It does not have model credentials or execute live smoke tests.

## Live smoke check

The owner authorized a small connectivity test, including possible usage-credit
consumption. Web search was disabled and both models used low effort.

| Model | Outcome | Reported input | Reported output |
|---|---|---:|---:|
| gpt-6-astra | Returned expected JSON | 9,164 tokens | 9 tokens |
| claude-opus-5 | Returned expected JSON | 312 tokens | 9 tokens |

Claude reported an API-equivalent estimate of $0.001785. That is diagnostic
metadata, not proof of which subscription/credit balance was charged.
Astra's client did not report a dollar amount. Neither response used reasoning/
thinking output tokens according to its usage metadata.

Two Astra smoke attempts failed while loading local configuration because the
smoke script tried to override a reserved built-in provider. The override was
removed, and the next attempt passed. No model response was generated by those
configuration failures.

The smoke record is stored locally under .mariana and is excluded from Git.
The production research gate remains disabled by default while provider overage
controls have not been confirmed off.

## What has not been established

- A complete live multi-round business research session.
- Actual search behavior and citation quality in both native clients.
- A real subscription-exhaustion/reset cycle across several days.
- Raspberry Pi installation, service startup, memory use or power-loss recovery.
- Improved business outcomes compared with a one-shot research baseline.

To evaluate quality, run the same problem once as a baseline and through several
MarianaBot rounds, then compare blind on factual accuracy, evidence quality,
economic realism, execution specificity and falsifiability. Track novel supported
findings and resolved blockers, not just the judge's score.
